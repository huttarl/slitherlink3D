Ideas for types of polyhedra to use for Slitherlink puzzles.
All of these will be convex (unless otherwise noted).

- General criteria:
    - Aesthetically pleasing
    - interesting variety
    - fairly "round" faces, as opposed to very long, narrow faces, which are difficult to show clues on or
    click on the edges of cleanly.
    - fairly uniformly sized faces, for the same reason as above: We don't want huge
    faces and tiny faces mixed, beyond a certain point.
    - enough faces/vertices/edges to make an interesting puzzle.
    - not so many f/v/e that it's overwhelming to think about.
    - fairly "spherical" (i.e. uniform distance from the center) shapes are preferred
    as easier to work with.
        - but some "exotic" shapes would be fun too, for variety. E.g. Johnson solids.
    - I don't know a technical reason why the polyhedra must be convex; the puzzle should be
     basically geometry-agnostic (only topology matters). But any significant
    concavity would make it hard to see or select the needed edges. Personally I don't like
    the stellated polyhedra much. But I'm open to changing my opinion on that.
    For example, https://en.wikipedia.org/wiki/Stellation#/media/File:First_stellation_of_icosahedron.svg
    wouldn't be too bad. We'd have to verify that the display and picking work correctly.
    - closed: I'm basically assuming all the shapes would be closed, but it wouldn't be
    impossible to include some "polyhedra" that had some faces removed. It would add interest,
    especially if we can see through the inside. We would have to make sure the opposite faces
    are visible from behind (less culling). And the puzzle generation code would have to make
    sure that no clues are placed on the removed faces.
    Update: we have some unclosed faces now, like nanotubes and capsid.

Specific shapes & categories:

- I wonder if there's some way to use stigmergy / "swarm intelligence" to generate interesting
    solids, seeding with some randomness but preferring a variety of face and vertex degrees.
    I don't know that stigmergy would change the algorithms much ... the idea is mainly to use
    the environment to deposit markers as external memory, influencing other agents to behave
    a certain way without direct communication.
    How about something like this: We start by generating a random spheroid solid, like we already
    do with genRandomPolyh.py. This gives us mostly triangles. Then, a bunch of ants start wandering
    randomly over the surface, from face to adjacent face. At each face F, they try to improve
    the structure: They try to join F with some adjacent triangular face G to form F', if they can do it without
    degrading the solid. That may involve moving G's other vertex V in order to make F' planar, and convex.
    A metric will determine whether the result is a better solid (we have some metrics like pointiness,
    planarity, etc.)
    The ants will try harder (try more candidate neighbors) if F's degree is 3 than 5.
    After a while, they're not going to be having much success in improving the structure. A metric
    about that says when to stop trying and return the result.
    I guess that's more just agentic than stigmergic. Maybe.
    (Maybe we could also have ants that travel from vertex to vertex, trying to improve their
    structure as well. Not sure what their criteria would be ...)
    - Maybe not stigmergy as such, but could start building a spherical polyhedron starting from
        several different points, each with a random style, then stitch the patches together
        where they meet. E.g. one with goldberg-like mesh (hexagons), one with zonelike (quads),
        one with geodesic (triangles).

- More surfaces with holes:
    - macaroni: half-tori, which avoid the topological problems of tori, are fun to work on,
        and can be mechanically different from tubes in that one side is curved differently
        from the other
    - spherical polyhedra with certain faces removed
- Non-convex polyhedra: this could be a big source of new grids, such as stellated and compound
    polyhedra. Maybe start with Escher's: https://www.georgehart.com/virtual-polyhedra/escher.html
    and simple ones from https://www.georgehart.com/virtual-polyhedra/stellations-info.html

- Randomness with (tetrahedral) symmetry is working well, especially with regularization.
  But we seem to have all vertices of degree 3.
